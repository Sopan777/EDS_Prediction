# EDS Prediction System — Audit, Root-Cause Analysis and Rebuild

Scope: the full pipeline in `d:\EDS\EDS_Prediction`, the three Material analysis
report PDFs, and `data/EDS Consolidation - Priority.xlsx`. Every claim below was
verified by running the code or reading the data; where a number is derived, the
derivation is named.

---

## 1. Executive Summary

The system produced confidently wrong material identifications. The reported
symptom — a high-Mn material predicted when input Mn < 0.5% — is real and
reproducible, but it is one instance of two systemic defects, not a missing
threshold.

**Measured baseline.** Against the six analyst-labelled particles in the report
PDFs, the shipped engine got **0 of 5 chemistries right** (the sixth has no
chemistry assigned), and returned **every wrong answer at confidence 1.00**:

| Input | Shipped engine | Report says |
|---|---|---|
| `{S: 0.2}` | `Guide Bush` **conf 1.00** | — (Guide Bush reference Mn is 1.12–1.60%; input Mn = 0) |
| `{Ni: 0.3}` | `Valve Piston` conf 1.00 | — (HSS identified by 0.3% Ni; V/W/Mo never checked) |
| 26-108 s1 | `Sealing Ring` conf 1.00 | **Plain carbon steel** |
| 26-108 s2 | `Magnet housing` conf 1.00 | **1.5 Mn Plain C steel** |
| 26-146 | `HP Sealing` conf 1.00 | **Cu Sn Metal matrix composite** |
| 26-130 s4 | `Unknown` | (no chemistry assigned) |

**Three findings reframed the work.**

1. **The prediction target was wrong.** The reports label a particle with a
   *chemistry class* plus a *list* of probable sources ("Injector Body, IC stud,
   VSS"; "Magnet Nut, NR nut??"). The system predicted one of 36 exact component
   names. On real component centroids with concentration-dependent σ, **20 of 630
   component pairs are indistinguishable at 3σ, and every one of those collisions
   is inside a single material family — zero cross-family** (§9). Component
   identity is not recoverable from EDS composition; family is.

2. **Real measured data existed but had been deleted** from the working tree
   while remaining in git. `data/EDS Consolidation.xlsx` — `Components` sheet —
   holds **173 real spectra across 43 labels**, uses `-` for not-measured as
   distinct from 0, and covers all 36 trained classes (30 with ≥3 spectra). Real
   within-component scatter is **2–6× the synthetic jitter** the rules were
   fitted to.

3. **Validation was circular.** `tests/conftest.py` kept a sample only if the
   engine already predicted it correctly, so 36 regression tests could not fail.
   The advertised 91.6% hides `Armature Bolt` at **5.0%** and `RLS Shim` at
   **5.2%**.

**Recommendation and outcome.** A deterministic, auditable compatibility engine
over a metal-normalised basis, targeting family → grade → ranked candidates, with
abstention as a first-class answer. ML is not viable as the primary
decision-maker — and not merely for want of data: the limit is
information-theoretic (§10). Implemented, the new engine scores **6/6** on the
real particles and **99.3% family accuracy under leave-one-component-out**, with
no confidently wrong answer outside a sub-family label (§15).

## 2. Current System Architecture

Two disjoint stacks that never meet.

**ML path** — `eds_pipeline.py` → `eds_extractor.py` → `predictor.py`, with
models in `models/` and training in `train_all_models.py`. Four tree models
(RandomForest, ExtraTrees, CatBoost, XGBoost), 18 features, 36 classes.

**Rule path** — `app_rule.py` → `rule_engine/engine.py` reading
`rule_engine/rules/rules.json` (36 rules, one per class), generated by
`training/train_rules.py`.

`eds_pipeline.py` imports only the ML predictor; `app_rule.py` only the rules.
There is **no hybrid, no ensembling and no conflict resolution**, because the two
never produce a prediction for the same input in the same process.

**Neither path was fully operational.** No `.pkl`/`.joblib`/`.cbm` exists
anywhere on disk, so `predictor.py:44-48` raises `FileNotFoundError` on every
call. The rule engine was the only working predictor.

## 3. Complete Prediction Pipeline Analysis

| Stage | What actually happened |
|---|---|
| Ingest | `eds_extractor.py` parses `pdftotext -layout`. **Broken on these reports** (§4). |
| Element naming | Canonicalised only on the PDF path. `data_utils.py:88` is an exact case-sensitive dict lookup, so `{"FE": 76.0}` silently scored as all-zeros. |
| Missing values | Missing key, `None`, `""`, `"-"`, `"N/A"` **all → `0.0`** (`rule_engine/preprocessing.py:66-78`, `data_utils.py:86-98`). No `nan`, no sentinel. |
| Feature selection | `config.py:38` and `rule_engine/preprocessing.py:18-25` classify **Fe, C, O as ID columns** and drop them. |
| Normalisation | None. Raw wt% into trees. No renormalisation, no scaling, no ratios. |
| Model | Not runnable (no artifacts). |
| Rules | Pure conjunctive AND (`rule_engine/models.py:69-75`). No score, no partial credit, no penalty. |
| Confidence | Static value frozen at training time (`engine.py:155-156`), identical for every matching input. |
| Thresholds | Advisory only. `predictor.py:150-151` sets a string flag; `engine.py:149-152` changes only `status`, never the prediction. |
| Conflict resolution | Sort keys `-validation_accuracy` then `-confidence` are set from the same value (`train_rules.py:261-262`), so the primary key and first tiebreak are degenerate. `priority` is computed, serialised, displayed and **never read**. |
| Post-processing | `app.py` majority vote hardcodes `flag=None` (`app.py:298`) and averages probability only over spectra where the winner already led — a biased estimator. |
| Validation | `rule_engine/validator.py` is never called at runtime and cannot veto anything. |

## 4. Findings from the EDS PDFs

Six labelled particles across three reports, transcribed with provenance into
`tests/data/real_particles.json` and verified against the PDF text: **16/16
spectra values, 6/6 chemistry strings, 12/12 source-list entries**.

**The reports' own answer format** is the key finding:

| Particle | Chemistry | Probable source | Uncertain? |
|---|---|---|---|
| 26-108 s1 | Plain carbon steel | Injector Body, IC stud, VSS | no |
| 26-108 s2 | 1.5 Mn Plain C steel | HPP, HPP sleeve | **??** |
| 26-130 s1/s2 | 1.5 Mn steel | Magnet Nut, NR nut | **??** |
| 26-130 s4 | *(none assigned)* | — | — |
| 26-146 | Cu Sn Metal matrix composite | Seal ring | no |

A chemistry class plus a **list**, with explicit `??` uncertainty. Never a single
component.

**Closure is a confounder.** Every table is "All elements analysed
(Normalised)", so each spectrum sums to 100%. Within one particle (26-130 s1),
C ranges **3.81 → 15.82 wt%**, dragging Fe from 79.87 → 93.16. Absolute wt% are
therefore not comparable between spectra. Renormalising over alloy elements only
collapses Fe's coefficient of variation from **5.96% → 0.67%**.

**Discriminating combinations, as they actually behave:**

- **Cr + Ni together** — 18/8 austenitic, Cr/Ni ≈ 2.0–2.4. Both must be
  *measured*; 26-108 s2 has neither in its column set, which is precisely why
  matching it to an austenitic grade was wrong.
- **Sn/Cu ≈ 0.10–0.12** — the CuSn bronze fingerprint. On 26-146 it is 0.107.
  Normalisation-invariant, so it survives the ~75% C+O+F dilution that makes
  absolute Cu unreliable. **No shipped rule referenced Cu or Sn at all.**
- **Mn alone** — separates plain-C from ~1.5Mn steel, and nothing else.
- **Zn/P at trace level** — a surface coating ("Traces of Zn" in 26-108 s1), not
  an alloy constituent. Treating it as one is what pulled that particle onto
  `Sealing Ring`.

**A second, previously unreported defect: the PDF extractor does not work.**
For 26-146 it returned `elements = ['O','F']` with every value `None`, against a
real table of C/O/F/Cr/Cu/Sn. Two independent causes, both verified:

1. `eds_extractor.py:147` splits on runs of **2+** spaces, but these tables
   separate narrow columns by a **single** space, so the header tokenises as
   `['Spectrum', 'In stats. C', 'O', 'F', 'Cr Cu', 'Sn Total']` — `C`, `Cr`,
   `Cu`, `Sn` never resolve.
2. Numeric cells are not aligned to the header's character offsets, so
   position-anchored slicing reads the wrong column.

Confirmed pre-existing by an old-versus-new behavioural diff. This blocked the
plan's primary verification gate and had to be fixed (§13).

## 5. Findings from `EDS Consolidation - Priority`

37 rows, one spectrum per component, 21 element columns. Rows sum to 100%.

- **No ranges, tolerances or impurity annotations.** A single point composition
  per component, so no band can be derived from this file alone.
- **Material grade populated for only 9 of 37 rows** — `Sl2 B1/ 100Cr6`,
  `VDSiCrDIN 17223-Sl2B4`, `X8CrNiS18-9(Comp of X12CrNiS19-8)`.
- **`Valve Nut` appears twice** with different compositions, so
  `component → composition` is not a function.
- **Element coverage is thin**: `K` nonzero in 0/37 rows; `Pb`, `Au`, `N`, `Ca`,
  `V`, `W` in exactly 1; `Mo`, `Zn` in 2.

**Grouping is respected at family level, not component level.** The three
`Sl2 B1/100Cr6` components (Armature Bolt/Guide/Plate, plus Ball Guide, C Shim,
Pille, Valve Piece) form one tight cluster — and the closest pairs in the whole
table are inside it (`Pille ↔ Valve Piece` L1 = 0.46 on metals). The three
`X8CrNiS18-9` components likewise. The old engine did **not** respect these
relationships: `Armature Bolt` and `C Shim` are separable only by Fe/C/O, which
were dropped, so both received fallback rules with **5.7%** and **6.2%**
precision.

**The recovered workbook is the more valuable file.** `data/EDS
Consolidation.xlsx` (deleted from the working tree, recovered from git HEAD) has
173 real spectra with `-` for not-measured, records surface preparation, and
shows that `M&M HPP Component` maps to **two different materials** by site —
Fe ≈ 96% steel on sites 1–3, Zn ≈ 93% coating on sites 4–5. Direct empirical
support for a many-to-many component↔material model.

## 7. Detailed Investigation of the Mn < 0.5% Issue

**Mechanism, established by reading the generator and reproducing the result.**

`training/train_rules.py:271-329` deletes conditions while *training-split*
precision stays ≥ 0.95 × the *validation-split* confidence recorded earlier at
line 261. Training precision is systematically higher, so the bar clears easily
and deletion runs aggressively. Critically, the criterion is precision against
the other 35 classes **in the synthetic dataset** — a bound is deleted whenever
no synthetic sample happens to occupy the region it guards. The bound is dropped
precisely because the data never tests it.

`rules.json:605-624` is the exhibit:

```json
{ "id": "rule_guide_bush_primary",
  "conditions": [ {"feature":"S","operator":">=","threshold":0.16},
                  {"feature":"Cr","operator":"<=","threshold":0.0} ],
  "prediction": "Guide Bush", "confidence": 1.0, "support": 80 }
```

Input `{S: 0.2}`: Mn is absent → coerced to `0.0`, and no condition mentions Mn.
Cr is absent → satisfies `<= 0.0` **vacuously**. Both conditions pass. Result:
`Guide Bush`, confidence 1.00, status `matched` — for a material whose every
reference spectrum carries 1.12–1.60 wt% Mn.

**Two compounding causes, not one.** Even had the Mn bound survived, the
`<= 0.0` upper bounds would still pass for free on any unreported element, so
sparse input is biased *toward* matching in general.

**This is not about Mn.** Auditing every rule against its own class statistics:

- **65 (rule, element) pairs are missing a lower bound** across **30 of 36
  rules**, where the element is materially present in that class. Worst:
  `Magnet Coil` Au 89.7%, `Clamping Saddle` Ni 81.5%, `Blade Terminal` Cu 47.8%,
  `Magnet housing` Cr 17.8%, `Locking Sleeve` Cr 17.4%. **Mn is one row of that
  table.**
- **351 pairs are missing an upper bound** — no foreign-element rejection.
- **2 rules were pruned to a single condition.**

**The inverse failure is the same bug.** 26-108 s2 (a plain 1.5Mn steel) matched
`Magnet housing` — X8CrNiS18-9, needing Cr ≈ 17.8 and Ni ≈ 8.1 — on
`S<=0.27 AND Mn>=1.39 AND Si>=0.33`. Neither Cr nor Ni was in the table's column
set, and the rule checks neither. The system understood neither presence nor
absence.

**Does it respect ranges and element roles?** No. There was no notion of major
versus trace: `Guide Bush`'s only positive condition was S ≥ 0.16, a
contamination-prone trace element, and 17 of 36 rules conditioned on trace Al,
which in a steel spectrum is as likely alumina polishing media as composition.

## 8. Root Causes

**RC1 — One coercion behind most failures.** Three semantically different
states collapse to the float `0.0`: never analysed, analysed-and-absent, and
measured-at-zero. `eds_extractor.py:177-190` correctly returns `None` for a blank
cell; `preprocessing.py:66-78` then destroys it.

**RC2 — Pruning validated against the wrong negatives** (§7). Regenerating
`rules.json` from the same synthetic CSV reproduces the pathology, so the rule
file had to be retired rather than repaired.

**RC3 — 84.6% of the measured mass discarded.** `config.py:38`. Also creates the
125 duplicate rows that inflate any random-split accuracy.

**RC4 — A boolean filter cannot express degree.** No score, so nothing can
register a composition-wide mismatch; and a static confidence cannot express fit.

**RC5 — No closure correction.** Absolute wt% are incomparable between spectra
(§4).

**RC6 — Circular validation concealed all of it.** Synthetic data is the
reference table plus jitter (per-class means reproduce the reference row to
< 0.05 wt%; every row sums to exactly 100.000), and the test fixture selected for
the property under test.

## 9. Material / Component Signature Analysis

Derived in `training/derive_knowledge.py` from the 173 real spectra. **Family
predicates are metallurgical standing knowledge, not fitted** — which is what
makes a single-member family usable: the system tests a specification rather than
fitting a distribution. **Element bands are derived from real spectra**, widened
by the fitted σ model, and flagged `provisional` where support is thin.

| Family | Label | Spectra | Components | Discriminators |
|---|---|---|---|---|
| F1a | Plain / low-Mn carbon steel | 61 | 15 | Mn, Fe |
| F1b | ~1.5 Mn plain carbon steel | 7 | 2 | Mn |
| F1c | Si-Cr spring steel | 17 | 5 | Si, Cr, Mn |
| F2 | Low-alloy Cr bearing steel (100Cr6) | 31 | 7 | Cr, Mn, Si |
| F3 | Tool / high-speed steel | 4 | 1 *(prov.)* | W, Mo, V, Cr |
| F4 | Austenitic stainless 18/8 | 10 | 3 | Cr, Ni, **Cr/Ni** |
| F5 | Ni-base alloy | 6 | 1 *(prov.)* | Ni, Cr, Fe |
| F6a | Cu-Sn bronze / MMC | 3 | 2 | Cu, Sn, **Sn/Cu** |
| F6b | Cu-Sn bronze layer on steel | 2 | 1 *(prov.)* | Cu, Fe, Sn, **Sn/Cu** |
| F7 | Au-plated contact | 6 | 2 | Au |
| F8a | Zn-coated steel | 6 | 2 | Zn, Fe |
| F8b | Zn-phosphate coating on steel | 19 | 2 | P, Zn, Fe |

**Separability, measured on real centroids with σ(x) = max(floor, cv·x):**

| Criterion | Colliding pairs (of 630) | Cross-family |
|---|---|---|
| 1σ on every element | 0 | 0 |
| 2σ | 14 | **0** |
| 3σ | 20 | **0** |

Every unavoidable confusion is *inside* a family — `Armature Bolt ↔ C Shim`,
`Nozzle Spring ↔ Valve Spring`, `Armature Shim ↔ CRI Shim`. This is the
quantitative basis for the target change.

**Uncertain, stated explicitly.** F3, F5 and F6b rest on one component each;
their bands are indicative. Per-element LOD is **not** fitted — it is a
provisional 0.10 wt% placeholder and must be confirmed against the instrument
before "analysed and absent" is treated as hard evidence. Carbon content is **not
determinable by EDS** at all, so no carbon grade may be claimed; every prediction
carries that caveat.

**Correction to an earlier figure in this project's own analysis.** The F1a/F1b
Mn boundary was first reported as a 4.7σ gap. That used within-*particle* repeat
noise (σ_Mn = 0.064), which is the wrong variance for assigning a *new* particle.
On within-*component* scatter (CV 13.8%) the same 0.30 wt% gap is **≈1.7σ**. It
therefore needs an ambiguity band, not a hard cut — and the real data agrees:
`M&M HPP Component` has spectra on both sides of it.

## 10. ML Model Assessment

- **Models**: four tree ensembles, fixed hyperparameters, no tuning
  (`models/*.py`).
- **Artifacts**: none exist. The path is non-functional as committed.
- **Training data**: 3582 rows, 36 classes, ~99/class — but the file is the
  37-row reference table plus multiplicative jitter (§8 RC6), with **no
  generator in the repo**. It contains no independent measurement information,
  so cross-validation on it is circular. Real within-component scatter is 2–6×
  larger, so the model was fitted to the wrong noise.
- **Class balance**: uniform, so imbalance is not the problem.
- **Features**: 18, excluding the matrix element. 125 duplicate rows can land on
  both sides of a random split, inflating test accuracy.
- **Calibration**: raw `predict_proba`, no calibration; RF/ET use
  `class_weight="balanced"` while CatBoost/XGBoost do not, yet one global
  threshold is applied to all.
- **Selection**: by mean accuracy across noise levels 10/25/50/100% **excluding
  clean** (`train_all_models.py:227-230`); 5-fold CV computed and never used.
- **OOD**: none. 304 and 316L both returned `Magnet housing` at confidence 1.00.

**Is ML appropriate here? Not as the primary decision-maker, and the reason is
not sample size.** Component identity is not recoverable from EDS composition
(§9) — more spectra cannot fix an information-theoretic limit. At family level,
families *are* specifications and several have one member, so there is nothing to
fit; a learned classifier could at best rediscover the hand-written predicate
while being unauditable in a customer-facing report.

## 11. Rule-Based Approach Assessment

**Where deterministic rules work well.** Element presence/absence with a real
detection limit; concentration bands with σ-derived tolerance; forbidden
elements; and above all **ratios** — `Cr/Ni` for austenitic, `Sn/Cu` for bronze —
which are normalisation-invariant and therefore survive the dilution that makes
absolute wt% unreliable. `Sn/Cu = 0.107` identifies the 26-146 particle that the
old engine missed entirely.

**Where naive rules fail, as this codebase demonstrates.** A conjunctive filter
cannot express degree, cannot rank, and treats a rule that lost nine of ten
conditions as a full match. Thresholds derived greedily from thin data delete
exactly the constraints that encode chemistry (§7). And "element present ⇒
candidate" mistakes a coating trace for a constituent.

**Maintenance.** Bands must be regenerated from data and versioned, never
hand-edited; family predicates change only with metallurgical knowledge. A new
material is added by writing one predicate plus its bands.

**Ambiguity and novelty** are handled by construction here: every matching family
is returned, so an ambiguous composition yields a *set*, and a composition
matching nothing is refused rather than forced to a nearest neighbour.

## 12. Hybrid Approach Assessment

A hybrid is only worth its complexity if each half contributes something the
other cannot. Assessed against the evidence:

| Candidate role for ML | Verdict |
|---|---|
| Filter impossible candidates before ML | Rules already do this deterministically and explainably. |
| Provide features to ML | No labelled data to train on (6 real particles). |
| Validate/override ML | There is no trustworthy ML output to validate. |
| Re-rank within a family | **Legitimate, later** — gated on ≥ 200 adjudicated particles. |
| Detect OOD compositions | **Legitimate now**, and unsupervised — no labels needed. |
| Impute unreported elements | **Never.** It would manufacture the evidence whose absence should trigger abstention. |

So the correct architecture today is **deterministic-first with ML reserved for
roles that need no labels** — novelty detection, multi-phase clustering, σ
estimation, and legacy-report mining to build the truth set. Calling that a
"hybrid" overstates it: ML currently belongs in data acquisition and quality
control, not in the decision.

## 13. Recommended Architecture (implemented)

```
PDF ─► eds_geometry.py ─► rule_engine/normalize.py ─► rule_engine/scoring.py ─► answer
       word-geometry        canonicalise names          hard feasibility
       tables               3-state missingness         soft σ-distance
       blanks preserved     dual basis + σ + ratios     ratio gates
                                                        evidence + margin
                                                        ─► family / set / unknown
```

**Responsibilities.** Rules own everything decisive: which elements must be
present, which are forbidden, concentration bands, ratio gates, and the
abstention decision. ML owns nothing in the decision path today.

**Elemental constraints.** Evaluated against measurement *state*, never a coerced
float:

| State | Required element | Merely allowed |
|---|---|---|
| `MEASURED` | must be in band ± 3σ | must not exceed the ceiling |
| `BELOW_LOD` | **contradiction** — family refused | passes |
| `NOT_ANALYSED` | **unevaluable** — cannot confirm, never passes | no information |

Only an element that *defines* a family, whose band rests on sufficient data,
may veto it; anything else out of band costs compatibility and is reported as
`unexplained_elements`. Both halves matter — vetoing on a one-spectrum incidental
band rejected the real bronze particle, while vetoing on nothing is the old
engine's 351 missing upper bounds.

**Groups.** Family → grade hint → ranked candidate components, many-to-many, so
`M&M HPP Component` can be both a steel and a Zn coating.

**Confidence.** `compatibility = exp(-½·d²) × evidence × quality`, capped at
**0.95**. It is a goodness-of-fit statistic, never a posterior — with six real
labelled particles no honest calibration is possible, and the old engine's 1.00
on impossible answers is exactly what must not recur.

**Ambiguity and novelty.** Four gates produce abstention: insufficient metal
signal, no feasible family, insufficient evidence, or a top-2 margin inside
measurement uncertainty. An ambiguous *set* is a legitimate answer — it is what
the analysts write as "Magnet Nut, NR nut??". An abstention lists **no**
candidates.

**Extending it.** Add a predicate to `FAMILY_DEFS`, re-run
`training/derive_sigma_model.py` then `training/derive_knowledge.py`. Nothing is
hand-edited; provenance and caveats are regenerated.

## 14. Prioritised Improvement Roadmap

**P0 — done.** Restore real data (`rule_engine/real_data.py`); three-state
missingness and dual basis (`normalize.py`); Fe/C/O restored; element
canonicalisation shared across paths (`canonical_element_symbol`, also fixed so
`Cu(wt%)` resolves while oxides reject); compatibility scoring with abstention
(`scoring.py`); σ model fitted from real repeat spectra
(`derive_sigma_model.py`); geometry-based PDF ingest (`eds_geometry.py`); legacy
suite quarantined and its fixture repaired; `pytest` added and requirements
pinned.

**P1 — accuracy.** Replace derived bands with DIN/EN specification ranges where
known (highest remaining accuracy lever, needs no EDS work); confirm per-element
LOD against the instrument; extend the ratio set; tune the F1a/F1b ambiguity band
on the real boundary; multi-phase detection for composites like 26-146.

**P2 — architecture.** Point `eds_pipeline.py` and `app_rule.py` at the new
engine and retire `rules.json` as a decision authority; call `validator.py` at
load so a bad knowledge base fails loudly; correct `README.md` and
`docs/RULE_ENGINE.md`, which document a `tests/test_rules.py`, a `saved_models/`,
an `outputs/` and a "98%+ ML ensemble" that do not exist.

**P3 — long term.** Mine the legacy report archive into a real labelled set
(highest-value ML application today); then novelty detection, family-level
re-ranking behind an explicit data gate, drift monitoring, analyst-feedback
capture.

Success is measured by §15, never by synthetic accuracy.

## 15. Validation and Testing Strategy

**Synthetic accuracy is not reported as a success criterion anywhere.** It
measures memorisation of a lookup table.

**Gate 1 — real labelled particles.** All six, `tests/test_real_particles.py`.
Correct family or explicit abstention; never a confident wrong answer.
**Was 0/5. Now 6/6.**

**Gate 2 — leave-one-component-out** (`training/validate_loco.py`). Bands
rebuilt from scratch without the held-out component, so this tests
generalisation, not recall:

| Metric | Result |
|---|---|
| Spectra swept | 173 |
| Answered | 140 (80.9%) |
| **Family correct** | **139/140 (99.3%)** |
| Family wrong | 1 — `F8a` vs `F8b`, both "coated steel" (sub-family label) |
| Abstained | 33 (19.1%) |

Abstentions are dominated by **21 "out of reference"** cases concentrated on
families whose *only* member was held out (F5, F3, F6b). With the sole member
removed the family has no bands, so abstaining is correct, not a miss.

**Gate 3 — component-level, reported separately and never averaged with family.**
Under LOCO it is not measurable by construction. Under leave-one-*spectrum*-out:
**148/162 recall (91.4%)**, median candidate-list size 7. Top-1 is deliberately
not a target (§9).

**Gate 4 — invariance** (`tests/test_scoring_invariance.py`): family prediction
unchanged as C+O varies 0→60%; scale, element-order and case invariance.

**Gate 5 — negative controls**: ten unsupported compositions must abstain,
including `{S:0.2}` as regression test #1, plus Ti-Al-V, polymer-like, and
implausible Mn/Cr.

**Gate 6 — chemical plausibility**: no answer may violate a required-element
floor or forbidden ceiling; no compatibility may reach 1.00; suspect input
(negative wt%, total > 100, duplicate key) is capped at 0.45 and flagged.

**Suite status**: 90 new tests pass; 158 legacy tests skipped by default. Run
with `--run-legacy` the repaired fixture exposes **4 real failures** —
`Armature Bolt`, `Armature Guide`, `RLS Shim`, `Valve Spring`, exactly the
classes measured at 5.0%, 62.9%, 5.2% and 33.0%, which previously reported green.

## 16. Edge Cases

All verified; abstention is the required behaviour unless noted.

| Case | Required | Result |
|---|---|---|
| Mn very low (0.05) | identify plain-C — low Mn *is* plain carbon steel | F1a |
| Mn very high (8.0) | abstain | abstains |
| Mn missing | may identify, reduced confidence | 0.50 |
| Cr very high (30) | abstain | abstains |
| Trace Si only / `{S:0.2}` / `{Ni:0.3}` | abstain | abstains |
| Empty, single element, unknown symbol | abstain / no crash | abstains |
| Case + annotation variants (`FE`, `fe`, `Fe(wt%)`) | resolve identically | F1b |
| Negative wt%, total > 100, duplicate key | cap + flag | 0.45 + caveat |
| Oxide formula (`Al2O3`) | reject, not read as Al | rejected |
| Polymer-like (no metal) | abstain | abstains |
| Heavy contamination (C+O 60%) | family unchanged | unchanged |
| Near-identical Fe/Cr/Ni siblings | family, plus multi-candidate caveat | as specified |
| Repeat spectra of one particle | pooled, not voted | pooled |
| Two-phase particle | contradiction disqualifies a family | enforced |
| Incomplete analysis (`CRI Sealing ring` r129, Fe and Cu not analysed) | abstain | abstains |

That last case deserves emphasis: it is the one real spectrum matching no
family. Fe and Cu — the two elements that decide a Cu-Sn seal ring — were not
analysed. Adding a predicate to "cover" it would over-fit a coverage metric and
let a partial spectrum produce a confident answer. Abstention is correct.

## 17. Risks and Limitations

- **Thin support.** F3, F5 and F6b rest on one component each; median 4 spectra
  per component supports family bands, not tight component bands. Flagged
  `provisional` rather than presented as firm.
- **LOD is a placeholder.** 0.10 wt% is not fitted. Until confirmed per element,
  "analysed and absent" is weaker evidence than the code's structure implies.
- **Coating threshold is a judgement call.** 3.0% of the alloy basis separates
  trace from layer; it is versioned in `normalize.py`, not hidden.
- **Family granularity is coarser** than a component name. Mitigated by the
  ranked list, and it matches how the reports are actually written.
- **Apparent accuracy will drop** relative to the advertised 91.6%, because that
  figure was circular. The honest baseline is 0/5 → 6/6 on real particles.
- **Carbon grades are unreachable** by EDS, permanently.
- **Two PDFs' statistics rows** parse correctly, but ingest is validated against
  three reports only; a differently formatted report may need work.

## 18. Open Questions / Missing Data

**Needed before component-level prediction is defensible — and it is not more
EDS.** Composition does not carry component identity (§9). What would: particle
morphology and size, hardness, coating presence/thickness, machining-mark and
fracture features, find location, and known-negative information (which
components are absent from that injector variant).

**Needed for firm bands (no EDS collection required).** DIN/EN specification
ranges for every injector alloy; the component↔grade map from the BOM per
variant, with assembly location; coating specifications.

**Needed for defensible tolerances.** Per-element LOD for the actual instrument;
repeat-spectra sets across ≥ 10 particles spanning the concentration range;
per-spectrum acquisition metadata (kV, standardless vs standards, dead time).

**Needed before any supervised ML.** ≥ 200 adjudicated particles with ≥ 20 per
family, full spectra with three-state missingness preserved, the analyst's
chemistry call and source list — plus an inter-analyst agreement study, since
that agreement is the ceiling on achievable accuracy.

**Unresolved.** Why the four `CRI_Material _Composition*` files and
`EDS Consolidation.xlsx` were deleted from the working tree. Whether
`synthetic_eds_data.csv` has a recoverable generator — if not it should be
deleted, as an unauditable file currently defining a system's behaviour is a
liability. Whether `Valve Nut` ×2 is two grades or two measurements. Whether
non-metallic particles (plastics, paints, sludge, shot-blast media) should become
first-class classes; today abstention is the mitigation, and the additional
sheets in the workbook are out of scope by direction.

---

## 19. Final Recommendation

**Adopt the deterministic compatibility architecture; do not invest further in
the ML path until the data gates in §18 are met.**

The evidence is consistent across code, PDFs and Excel. The failures were not
tuning problems: three measurement states collapsed into one float, necessary
constraints deleted by a pruner validated against synthetic negatives, 84.6% of
the measured mass discarded, a boolean filter that cannot express degree, and a
confidence number frozen at training time — all concealed by validation that
could not fail.

Changing the target from component to **family → grade → ranked candidates** is
the single most consequential decision, and it is forced by the data rather than
chosen for convenience: at 3σ, 20 of 630 component pairs are indistinguishable
and **none** of those collisions crosses a family boundary. It also matches how
the analysts already write their reports.

Two principles should outlast this document. **Absence must never satisfy a
constraint** — that one rule eliminates the reported bug and the 65 missing-bound
failures with it. And **abstention is a first-class answer**: on a
failure-analysis report that reaches a customer, "insufficient evidence, Cr and
Ni were not analysed" is worth more than a component name at confidence 1.00 that
the chemistry contradicts.

Measured outcome: real-particle accuracy **0/5 → 6/6**, LOCO family accuracy
**99.3%**, zero confidently wrong answers outside a sub-family label, and every
threshold traceable to measured data or an explicitly flagged assumption.
